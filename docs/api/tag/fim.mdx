#### model \(required\): <code>string</code> \{#operation-fim_completion_v1_fim_completions_post+request+model\}

ID of the model to use. Only compatible for now with:
  - `codestral-2405`
  - `codestral-latest`

_Example:_

```

```

#### prompt \(required\): <code>string</code> \{#operation-fim_completion_v1_fim_completions_post+request+prompt\}

The text/code to complete.

_Example:_

```
def
```

#### random\_seed: <code>integer | null</code> \{#operation-fim_completion_v1_fim_completions_post+request+random_seed\}

#### stop: <code>string | array&lt;string&gt;</code> \{#operation-fim_completion_v1_fim_completions_post+request+stop\}

Stop generation if this token is detected. Or if one of these tokens is detected when providing an array

#### stream: <code>boolean</code> \{#operation-fim_completion_v1_fim_completions_post+request+stream\}

Whether to stream back partial progress. If set, tokens will be sent as data-only server-side events as they become available, with the stream terminated by a data: [DONE] message. Otherwise, the server will hold the request open until the timeout or until completion, with the response containing the full result as JSON.

_Default Value:_ `false`

#### suffix: <code>string | null</code> \{#operation-fim_completion_v1_fim_completions_post+request+suffix\}

_Example:_

```
return a+b
```

#### temperature: <code>number | null</code> \{#operation-fim_completion_v1_fim_completions_post+request+temperature\}

#### top\_p: <code>number</code> \{#operation-fim_completion_v1_fim_completions_post+request+top_p\}

Nucleus sampling, where the model considers the results of the tokens with `top_p` probability mass. So 0.1 means only the tokens comprising the top 10% probability mass are considered. We generally recommend altering this or `temperature` but not both.

_Default Value:_ `1`
